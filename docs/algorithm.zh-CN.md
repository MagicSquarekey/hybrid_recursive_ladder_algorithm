# 混合递归阶梯算法（Hybrid Recursive Ladder Algorithm）

> 本文是算法的中文规范。实现与测试以本文和 [algorithm.md](algorithm.md) 为准；口径变更必须同步更新。

## 一、定义

把一个查询区间 `[start, end)` 按 **月 → 日 → 时 → 分** 递归分解：

1. 每一层只取**完整包含在区间内**的单位；
2. 不完整的左残段 / 右残段交给下一层继续分解；
3. 最细层（默认「分」）的残段（不足一分钟）作为「零头」单独成段，按原始点取值。

命名为**混合递归阶梯**：从粗到细逐层下台阶，每级台阶只踩完整的砖。

## 二、边界规则（不可协商）

| 规则 | 说明 |
|---|---|
| 左闭右开 | `[start, end)`。若 end 正好是整点，该整点**不属于**区间（如 20:00:00 为终点，则「20 时」不存在） |
| 只取完整单位 | 单位 `[u, u+1)` 必须整体落在 `[start, end)` 内才作为本层的一段 |
| 时区 | 按配置的 IANA 时区对齐（默认 `Asia/Shanghai`）；月=自然月首日 00:00，日=00:00，时=整点，分=整分 |
| 单位序列 | 月 → 日 → 时 → 分；最细层可配置（`month/day/hour/minute`） |
| 完整性基准 | 以**查询区间**为准，不以当前时间为准 |
| 不变量 | 段与段首尾相接、不重不漏，并集恰为 `[start, end)` |

## 三、伪代码

```
ladder(a, b, level):
    if a >= b: return []

    if level 是最细层:
        emit(a, b)                       # 完整单位或零头
        return

    if unit_start(a, level) != a:        # 左残段
        nb = next_boundary(a, level)
        if nb >= b:
            ladder(a, b, next_level)
            return
        ladder(a, nb, next_level)
        a = nb

    while next_boundary(a, level) <= b:  # 完整单位逐个剥离
        nb = next_boundary(a, level)
        emit(a, nb, level)
        a = nb

    if a < b:                            # 右残段
        ladder(a, b, next_level)
```

`next_boundary` 必须严格前进；实现里对「不前进」做了防御性报错。

## 四、示例

查询 `2026-01-01 00:00:00 → 2026-10-21 18:49:59`：

| 层级 | 段 | 数量 |
|---|---|---:|
| 月 | 2026-01 ~ 2026-09 | 9 |
| 日 | 10-01 ~ 10-20 | 20 |
| 时 | 10-21 00:00 ~ 17:00 | 18 |
| 分 | 18:00 ~ 18:48 | 49 |
| 零头 | 18:49:00 – 18:49:59 | 1 |
| **合计** | | **97** |

逐分钟是 423,049 个桶，压缩约 **4,360 倍**。

注意 18 时（18:00–19:00）不完整，所以完整小时只到 17 时；18 时被拆成 49 个完整分钟 + 1 个 59 秒零头。

## 五、取数策略

**层的划分只决定输出粒度，不决定请求粒度。** 每一层用「下一层聚合」一次拉取，再本地折叠：

| 输出层 | 取数层 | 说明 |
|---|---|---|
| 月 | 日 | 多数数据源没有自然月固定 interval，拉日级后本地按月折叠 |
| 日 | 时 | 避免 DST / 固定桶导致的日边界漂移 |
| 时 | 分 | 拉分钟级后按小时折叠 |
| 分 | 分 | 直接分钟级 |
| 零头 | 原始点 | 区间聚合无法表示不足一分钟的段 |

### 5.1 分组规则（v0.0.1 修正）

取数分组必须按 **取数层级 + 时间连续性**，不能只按时间连续性。小时段和分钟段可以共用一次分钟级取数；月段和日段不能共用。原 AutoTestHub 实现只按相邻分组，导致多层级区间被整体按最粗层取数，小时/分钟段取值错位。

### 5.2 请求数

大约为：

```
ceil(日总数 / max_intervals) + ceil(小时总数 / max_intervals)
+ ceil(分钟总数 / max_intervals) + 1（零头，如有）
```

`max_intervals` 默认 500（TB 实测 700 可、800 拒，文档常说的 1000 不可信）。10 个月查询通常 5–7 次请求。5.4 节给出按 run 分窗的精确模型。

### 5.3 细化的局部性

记 `L_0 = 月`、`L_1 = 日`、`L_2 = 时`、`L_3 = 分`（由粗到细），`U_i(t)` 表示包含 `t` 的 `L_i` 层单位，`k` 为层数（默认层级为 4）。若一个单位整体落在 `[s, e)` 内，称它是**完整**的。

**引理 1（两边引理）.** 对任意 `i < k - 1`，从 `L_i` 层传给 `L_{i+1}` 层的区间，最多落在 `L_i` 的两个单位内：包含 `s` 的单位，以及包含 `e - 1` 的单位。`L_i` 层的完整单位都在本层输出，不会继续下沉。

*证明.* `L_i` 层的 walk 只做三件事：(i) 当 `s` 未对齐时，把左残段 `[s, next_boundary(s))` 下沉；(ii) 输出一段完整的单位；(iii) 当 `a < e` 时，把右残段 `[a, e)` 下沉。第 (i) 步在 `U_i(s)` 内；第 (iii) 步在 `U_i(e - 1)` 内；第 (ii) 步只输出，不递归。每个被下沉的残段都短于该层的一个单位，也就是低于该层的最大基数（31 天、24 小时、60 分钟）。∎

**命题 2（细化有界）.** 记 `N_j` 为 `L_j` 层输出的段数。对任意 `i`，

```
sum_{j > i} N_j  <=  B_i
```

其中 `B_i` 是把至多两个 `L_i` 单位一直分解到最细层时能产生的最大段数。`B_i` 只取决于日历层级本身，与区间长度无关。

对标准层级且 `finest = minute`，一个保守上界是：

```
N_day    <= 2 * 31 = 62      # 最多两个不完整月
N_hour   <= 4 * 24 = 96      # 每个不完整月至多两个不完整日
N_minute <= 8 * 60 = 480     # 每个不完整日至多两个不完整时
tail     <= 1
```

因子逐层翻倍：每个不完整单位最多产生两个下一层的不完整单位。这些上界是保守值，不是紧确值。四项相加得到 `N <= N_month + 639`，其中 `N` 是总段数。

**推论 3（段数增长）.** 总段数为 `N_month + O(1)`。它随完整月的数量（最粗输出层）增长，而不随分钟桶数量增长。对 `Y` 年的区间，`N = O(Y)`；逐分钟查询则是 `O(Y * 525600)`。

**命题 4（递归深度）.** `walk` 的递归深度不超过层数 `k`（月到分是 4）。每次递归把层级索引加一，基准情形是最细层。

### 5.4 请求数模型

令 `K = max_intervals`，把「取数层级相同且时间连续」的最大连续段称为一个 **fetch run**（见 5.1）。设一个 run 的时长为 `T`、取数桶长为 `Δ`，适配器按 `K * Δ` 分窗，发出

```
r(run) = ceil(T / (K * Δ))
```

次聚合请求。因此总请求数为

```
R_agg = sum over runs r of ceil(T_r / (K * Δ_r)).
```

这就是 `ThingsBoardSource.interval_agg` 的实际模型：引擎每个 run 调一次适配器，适配器内部负责分窗。记 `B_F` 为整个区间在取数层级 `F` 上的桶总数；它不等于输出段数。

常见的连续情形最多有三个聚合 run（日、时、分），所以求和最多三项。10 个月示例、`K = 500`：

```
月        -> 按日取数：  273 个桶 -> 1 次请求
日        -> 按小时取数：480 个桶 -> 1 次请求
时 + 分   -> 按分钟取数：1,129 个桶 -> 3 次请求
R_agg ~= 5
```

由引理 1，`B_day = O(N_month)`；`B_hour` 和 `B_minute` 只落在两个不完整月及其边缘的不完整日内，对固定层级是 `O(1)`。因此

```
R_agg = O(N_month / K + 1)。
```

请求数随「完整月数 / 上限」增长，不随分钟桶数增长。零头的原始点请求与数据密度有关：每次最多返回 `max_points` 个点，满页则二分（见第八节），`P` 个点需要 `O(P / max_points)` 次请求，下限是 `min_bucket_ms`。

### 5.5 折叠正确性（对齐条件）

`fold_sum` 按桶的**起点**把桶归到包含它的输出段。如果每个取数桶都完整落在某个输出段内、或与输出段不相交，折叠和就等于数据源在该段上的和。固定偏移时区满足这个条件：每个日历单位都是固定长度桶的并集。DST 时区里，日/时的边界可能落在一个固定长度桶内部；此时应在切换点附近使用更细的取数层或原始点。这是一个正确性条件，不是对任意时区的普遍结论。

## 六、规则正确性

| 规则 | 阶梯是否精确 | 说明 |
|---|---|---|
| sum（增量求和） | ✅ 精确 | 各段之和 = 总和。**v0.0.1 只实现此规则** |
| max / min | ✅ 精确 | 段极值再取极值（未实现） |
| last | ✅ 精确 | 末段末值 = 总末值（未实现） |
| avg | ⚠️ 需加权 | 段均值的平均 ≠ 全部点的平均；需同时取 sum 与 cnt（未实现） |
| meter_delta（累计量差分） | ⚠️ 换算法 | 需要每段首值；TB 没有 FIRST 聚合（未实现） |

### 6.1 空段 vs 零值

`value = null` 表示无采样；`value = 0.0` 表示有采样但求和为 0。接口、存储、界面都必须严格区分。

### 6.2 时间完整 vs 数据完整

算法只保证**时间完整**（段落在区间内）；**数据完整**由数据源决定。合计是「实际存在的点」的和，数据缺失时合计会偏小，但加法本身没错。用 `cnt`（实际点数/桶数）和 `expected`（应有桶数）标记稀疏程度，不做补数。

## 七、覆盖与本地优先读路径

### 7.1 覆盖

固化完成后登记 `(start_ts, end_ts, covered_at)`。只登记到 `now - grace`（默认 5 分钟），正在发生的尾段永远不算可信本地。未覆盖段查完数据源后**无论有没有数据都登记**（「这段查过了」），避免下次重复请求。

### 7.2 子区间切分

对每个段：

1. 按合并后的覆盖区间切成「已覆盖 / 未覆盖」子区间；
2. 已覆盖部分用一条批量 SQL 求和；
3. 完整未覆盖的段走分组聚合（请求最省）；
4. 部分覆盖的段，数据源只补缺的那一截，桶长自适应：
   `max(min_bucket, ceil(duration / max_intervals / min_bucket) * min_bucket)`；
5. 段值 = 本地部分 + 数据源部分；来源标 `local / tb / mixed / empty / uncovered`。

结果里的 `tb_ranges` 是所有未覆盖子区间合并后的列表，直接作为固化的输入。

### 7.3 重写安全

重写一个区间前，先清除与该区间重叠的覆盖记录。如果拉取中途失败，该区间不再被标记为「已覆盖」，下次查询会重新拉取，而不是信任不完整的本地数据。

## 八、固化、校验与修复

* **固化**：按每块 ≤ `max_points`（默认 1 万点）流式拉原始点，命中上限自动二分；按主键幂等写入；写完登记覆盖。
* **校验**：先段级比对 SUM 与点数，差异段再逐点定位，统计 `added / removed / changed` 与样例时间戳；逐点展开最多 `drill_limit`（默认 50）段。
* **修复**：按 `max_repair_days`（默认 366 天）分窗，删除本地区间并从数据源重拉，重新登记覆盖。数据源已删除的点会在本地消失。

## 十、不变量

1. 段精确铺满区间；
2. 不产生零长段；
3. 单位只有完整时才在本层输出；
4. `null` 与 `0.0` 严格区分；
5. 覆盖不越过 `now - grace`；
6. 固化幂等；
7. 算法只读数据源，不写数据源。

## 十一、已知限制

* v0.0.1 只实现 `sum`。
* 数据缺失会让合计偏小；`cnt/expected` 只暴露稀疏，不补数。
* TB 的 `COUNT` 会吞同分钟重复点；精确点数要拉原始点。
* 进程内后台任务重启即丢（结果可重算，固化数据不丢）。
* 固定桶长意味着日/时折叠适合固定偏移时区（如 `Asia/Shanghai`）；DST 时区在切换点附近建议用更细的取数层。
* 原 AutoTestHub 的 `device_id` 稳定键迁移不自动完成，见 `docs/architecture.md`。

## 十二、与已知技术的关系

分解是线段树所用「规范区间分解」在日历混合进制上的实例：用对齐单位覆盖区间，把不完整的边推到更细层。区别在目标——线段树合并兄弟节点来回答一个聚合值；ladder 必须为每个输出单位返回一个值，所以不能跨层合并，只能输出每个完整单位，并用层级来规划抓取。折叠是 roll-up/consolidation，方向和 RRDtool 的 RRA consolidation、BTrDB 的节点统计、OLAP roll-up 一致。这里的贡献是组合：在「每请求桶数有上限」的约束下，跨日历经度做一次请求计划，并用本地覆盖补缺口。它面向只暴露只读区间聚合接口的源端，不要求写入或改动源端的存储/降采样策略。完整对比与引用见 [`related-work.zh-CN.md`](related-work.zh-CN.md)。
